# 分布式架构下的大区选择方案（轻量级）

## 核心思路
不改变现有架构，仅在现有协议上扩展，让客户端：
1. **登录校验** → LoginServer（不变）
2. **拉取大区列表** → DirectoryServer（新增接口）
3. **用户选择大区** → 客户端UI
4. **直连目标服务器** → LogicServer（不变）

## 协议扩展（最小改动）

### 1. 在现有 `directory.proto` 中添加大区查询

    int32 estimated_ping = 8;      // 预估延迟(ms)
    repeated string labels = 9;    // 标签：["pvp", "new", "beginner"]
}

message RegionQueryResponse {
    repeated RegionInfo regions = 1;
    int64 server_time = 2;
}

## 实现方案

### 1. DirectoryServer 增强（1-2天）

```csharp
// DirectoryServer/Handlers/RegionQueryHandler.cs
public class RegionQueryHandler : IMessageHandler
{
    private readonly IServerRegistry _registry;
    
    public async Task<envelope> HandleAsync(envelope request, CancellationToken ct)
    {
        var regionReq = RegionQueryRequest.Parser.ParseFrom(request.Payload);
        
        // 1. 获取所有在线服务器
        var allServers = await _registry.GetAllAsync();
        
        // 2. 按 region 分组聚合
        var regions = allServers
            .GroupBy(s => s.Region)
            .Select(g => new RegionInfo
            {
                RegionId = g.Key,
                RegionName = GetRegionName(g.Key),  // 从配置映射
                TotalServers = g.Count(),
                TotalPlayers = g.Sum(s => s.PlayerCount),
                AvgLoad = g.Average(s => s.Load),
                Status = CalculateRegionStatus(g),
                IsRecommended = IsRecommendedRegion(g.Key),
                EstimatedPing = EstimatePing(g.Key),
                Labels = GetRegionLabels(g.Key)
            })
            .OrderBy(r => r.RegionName)
            .ToList();
        
        // 3. 构建响应
        var response = new RegionQueryResponse
        {
            Regions = { regions },
            ServerTime = DateTimeOffset.UtcNow.ToUnixTimeSeconds()
        };
        
        return new envelope
        {
            Type = "REGION_QUERY_RESPONSE",
            Payload = response.ToByteString(),
            RequestId = request.RequestId
        };
    }
    
    private string GetRegionName(string regionId)
    {
        // 从配置读取大区名称映射
        var regionMap = new Dictionary<string, string>
        {
            ["cn-east-1"] = "华东一区(上海)",
            ["cn-east-2"] = "华东二区(杭州)",
            ["cn-south-1"] = "华南一区(广州)",
            ["cn-north-1"] = "华北一区(北京)",
            ["cn-west-1"] = "西南一区(成都)"
        };
        return regionMap.GetValueOrDefault(regionId, regionId);
    }
}
```

### 2. 客户端流程（UI 层）

```csharp
// Unity 客户端伪代码
public class RegionSelectionUI : MonoBehaviour
{
    public async void OnLoginSuccess(string token)
    {
        // 1. 连接 DirectoryServer（已知地址）
        var directoryClient = new GameClient("directory-server-ip", 5502);
        
        // 2. 请求大区列表
        var regionRequest = new envelope
        {
            Type = "REGION_QUERY_REQUEST",
            Payload = new RegionQueryRequest { Token = token }.ToByteString(),
            RequestId = Guid.NewGuid().ToString()
        };
        
        var response = await directoryClient.SendAsync(regionRequest);
        var regionList = RegionQueryResponse.Parser.ParseFrom(response.Payload);
        
        // 3. 显示大区选择界面
        ShowRegionList(regionList.Regions);
    }
    
    public async void OnRegionSelected(string regionId)
    {
        // 4. 再次查询该大区的 LogicServer 列表
        var serverQuery = new envelope
        {
            Type = "SERVER_QUERY_REQUEST",
            Payload = new ServerQueryRequest 
            { 
                ServerType = "logic",
                Region = regionId,
                Strategy = "load"
            }.ToByteString(),
            RequestId = Guid.NewGuid().ToString()
        };
        
        var response = await directoryClient.SendAsync(serverQuery);
        var serverList = ServerQueryResponse.Parser.ParseFrom(response.Payload);
        
        if (serverList.Servers.Count == 0)
        {
            ShowError("该大区暂无可用服务器");
            return;
        }
        
        // 5. 客户端本地智能选择（简单负载均衡）
        var selectedServer = SelectServerLocally(serverList.Servers);
        
        // 6. 直连选中的 LogicServer
        ConnectToLogicServer(selectedServer.Host, selectedServer.Port);
    }
    
    private ServerInfo SelectServerLocally(List<ServerInfo> servers)
    {
        // 简单策略：选择负载最低的
        return servers.OrderBy(s => s.Load).FirstOrDefault();
        
        // 或：随机选择（避免所有客户端打向同一台）
        // return servers[Random.Range(0, servers.Count)];
    }
}
```

## 架构对比

| 方案 | 优点 | 缺点 | 适合场景 |
|------|------|------|----------|
| **集中式（Login路由）** | 服务端完全控制路由策略 | Login成为单点，增加一跳延迟 | 需要精细控制路由策略 |
| **分布式（客户端选择）** | 无单点，延迟最低，架构简单 | 客户端逻辑复杂，策略难统一 | 追求极致性能，信任客户端 |

### 客户端本地负载均衡策略

```csharp
// 可配置的客户端路由策略
public enum ClientRoutingStrategy
{
    LoadBalancing,      // 负载均衡（默认）
    LowestLatency,      // 最低延迟
    Random,             // 随机选择
    Affinity,           // 亲和性（上次连接的服务器）
    CapacityFirst       // 容量优先
}

public class ClientRouter
{
    public ServerInfo SelectServer(List<ServerInfo> servers, ClientRoutingStrategy strategy)
    {
        return strategy switch
        {
            ClientRoutingStrategy.LoadBalancing => 
                servers.OrderBy(s => s.Load).FirstOrDefault(),
                
            ClientRoutingStrategy.LowestLatency => 
                servers.OrderBy(s => s.LastHeartbeat).FirstOrDefault(), // 简单用心跳时间近似延迟
                
            ClientRoutingStrategy.Random => 
                servers[Random.Shared.Next(servers.Count)],
                
            ClientRoutingStrategy.Affinity => 
                GetAffinityServer(servers) ?? servers.FirstOrDefault(),
                
            ClientRoutingStrategy.CapacityFirst => 
                servers.OrderByDescending(s => s.Capacity - s.PlayerCount).FirstOrDefault(),
                
            _ => servers.FirstOrDefault()
        };
    }
}
```

## 监控与运维

### 大区状态看板

```csharp
// 监控大区健康状态
public class RegionMonitor
{
    public RegionHealth GetRegionHealth(string regionId)
    {
        var servers = _registry.GetByRegion(regionId);
        
        return new RegionHealth
        {
            RegionId = regionId,
            TotalServers = servers.Count,
            OnlineServers = servers.Count(s => s.Status == "online"),
            TotalPlayers = servers.Sum(s => s.PlayerCount),
            AvgLoad = servers.Average(s => s.Load),
            HealthScore = CalculateHealthScore(servers),
            Issues = DetectIssues(servers)
        };
    }
    
    private List<string> DetectIssues(List<ServerInfo> servers)
    {
        var issues = new List<string>();
        
        if (servers.Count == 0)
            issues.Add("无在线服务器");
            
        if (servers.Any(s => s.Load > 0.9))
            issues.Add("有服务器负载过高");
            
        if (servers.Any(s => DateTimeOffset.UtcNow.ToUnixTimeSeconds() - s.LastHeartbeat > 60))
            issues.Add("有心跳超时服务器");
            
        return issues;
    }
}
```

## 总结

**保持分布式架构 + 客户端大区选择** 是最小改动、最大兼容的方案：

1. **不改动核心架构**：Login/Directory/Logic/Battle 职责不变
2. **协议简单扩展**：仅新增大区查询消息类型
3. **客户端自主选择**：客户端根据本地策略选择服务器
4. **运维友好**：大区状态清晰可见，可独立维护

**推荐理由**：
- 保持现有架构的所有优势（低延迟、无单点、易扩展）
- 实现成本低（1周内可上线）
- 用户体验良好（大区选择 → 直连游戏）
- 未来可演进（如需服务端智能路由，可逐步迁移）
