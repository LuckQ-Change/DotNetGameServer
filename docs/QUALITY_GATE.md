# 质量门禁与完成定义

框架变更只有同时满足以下条件才算完成：

| 维度 | 验收条件 |
|---|---|
| 构建 | Release 构建零警告；警告按错误处理 |
| 格式与代码样式 | `dotnet format --verify-no-changes --severity warn` 通过 |
| 测试 | 单元测试、TCP 集成测试、跨服 RPC 与 Unity 协议契约测试全部通过；服务器行覆盖率 ≥ 60%，分支覆盖率 ≥ 45% |
| 依赖 | 使用中央版本管理和锁文件；Restore 开启 NuGet Audit |
| 跨平台 | Windows 与 Linux CI 同时通过 |
| 安全 | 输入长度、鉴权边界、TLS 截止时间和生产密钥守卫有明确行为 |
| 生命周期 | 启动失败可逆序回滚，停服有截止时间，服务发现主动注销 |
| 可观测性 | liveness/readiness 分离；请求、连接和 RPC 指标无实例引用泄漏 |
| 兼容性 | Protobuf 字段编号只追加；破坏性 API 变更提供迁移说明 |
| 文档 | 示例命令经过验证，配置默认值与代码一致 |

CI 会执行锁定还原、格式验证、严格构建、带覆盖率采集的测试和 Demo 发布。覆盖率是发现未测试分支的信号，不以追求单一百分比替代关键路径测试。
