# 客户端接入文档

本项目使用 Protobuf 定义强类型消息，通过 TCP 进行通信。客户端通过目录服务器发现可用的具体服务（登录、资源、逻辑、战斗等），然后与目标服务建立连接并交换请求/响应消息。

## 总览
- 目录服务器：查询可用服务器列表（类型、地址、端口、状态）。
- 登录服务器：登录鉴权，签发会话或令牌（如后续需要）。
- 资源服务器：查询版本与获取资源包（AB）；不再使用服务端版本匹配作为强制更新依据。
- 逻辑服务器：业务逻辑（示例为签到）。
- 战斗服务器：战斗相关逻辑（示例为开始战斗、攻击）。

## 协议与消息
- 使用 `Google.Protobuf` 生成的消息类型，命名空间为 `DotNetGameServer`。
- 客户端和服务器都通过强类型请求/响应交互，例如：
  - 资源：`QueryVersionRequest` → `QueryVersionResponse`，`GetBundleRequest` → `GetBundleResponse`
  - 逻辑：`QuerySignInStatusRequest` → `QuerySignInStatusResponse`，`ClaimSignInRewardRequest` → `ClaimSignInRewardResponse`
  - 战斗：`StartBattleRequest` → `StartBattleResponse`，`AttackRequest` → `AttackResponse`
- 目录：`QueryServersRequest` → `QueryServersResponse`，用于服务发现。

## 连接流程
1. 连接目录服务器（默认 `127.0.0.1:5500`，可配置）。
2. 发送 `QueryServersRequest`，过滤需要的服务类型（如 `resource`、`login`、`logic`、`battle`）。
3. 选择一个可用服务器（根据 `status`, `capacity`, `region` 等）。
4. 连接所选服务器，发送对应业务请求，接收响应并处理。

## 客户端示例（C#）
> 下述示例演示通过 TCP 使用 Protobuf 序列化与服务器交互的基本思路。实际长度前缀与封包格式需与服务器实现一致（本项目采用长度前缀 + Protobuf 序列化）。

```csharp
using System.Net.Sockets;
using Google.Protobuf;
using DotNetGameServer;

static async Task SendMessageAsync<TReq, TResp>(TcpClient client, IMessage req)
    where TResp : class, IMessage, new()
{
    var stream = client.GetStream();

    // 序列化请求
    var reqBytes = req.ToByteArray();
    var len = BitConverter.GetBytes(reqBytes.Length);
    await stream.WriteAsync(len, 0, len.Length);
    await stream.WriteAsync(reqBytes, 0, reqBytes.Length);

    // 读取响应长度
    var lenBuf = new byte[4];
    await stream.ReadExactlyAsync(lenBuf, 0, 4);
    var respLen = BitConverter.ToInt32(lenBuf, 0);
    var respBuf = new byte[respLen];
    await stream.ReadExactlyAsync(respBuf, 0, respLen);

    // 解析响应
    var resp = new TResp();
    resp.MergeFrom(respBuf);
    Console.WriteLine($"收到响应: {resp}");
}

// 查询目录服务器，随后连接资源服务器查询版本
static async Task DemoQueryVersionAsync()
{
    // 连接目录服务器
    using var dirClient = new TcpClient();
    await dirClient.ConnectAsync("127.0.0.1", 5500);

    // 查询资源服务器列表
    var q = new QueryServersRequest { Type = "resource" };
    await SendMessageAsync<QueryServersRequest, QueryServersResponse>(dirClient, q);
    // 根据返回的服务器条目，选择一个地址端口（此处略，假设为 127.0.0.1:5600）

    // 连接资源服务器
    using var resClient = new TcpClient();
    await resClient.ConnectAsync("127.0.0.1", 5600);

    // 查询版本
    var qv = new QueryVersionRequest { Platform = "windows" };
    await SendMessageAsync<QueryVersionRequest, QueryVersionResponse>(resClient, qv);
}
```

## 常见交互示例
- 登录流程（示例，按实际 Handler 实现为准）：
  1) `LoginRequest` → `LoginResponse` 获取会话/令牌；
  2) 后续访问逻辑/资源服务时携带令牌（如果服务端启用校验）。

- 七日签到：
  - 查询状态：`QuerySignInStatusRequest` → `QuerySignInStatusResponse`；
  - 领取奖励：`ClaimSignInRewardRequest` → `ClaimSignInRewardResponse`。

- 资源获取：
  - `QueryVersionRequest` → 返回最新版本信息与资源清单；`update_available` 字段仅供参考，当前服务端始终返回 `false`；请以清单（`bundles`）为准执行更新。
  - `GetBundleRequest` → 返回指定资源包信息或下载地址。

## 约定与错误处理
- 长度前缀为 4 字节小端整数，后跟 Protobuf 字节序列。
- 单包最大长度可通过服务器 `ServerSettings.MaxMessageSizeBytes` 配置（默认 1MB）。
- 超时与重试：客户端应设置适当的读写超时并进行重试。
- 错误响应：各服务可通过响应内的错误码/消息字段返回错误（按具体响应结构处理）。

## 跨语言接入
- 通过 `.proto` 文件生成对应语言的 Protobuf 类（参见 `tools/gen-proto.ps1`）。
- 采用一致的长度前缀 + Protobuf 序列化封包策略。

## 调试建议
- 先接入资源服务器的 `QueryVersionRequest` 作为最小闭环测试。
- 使用目录服务器进行服务发现，避免硬编码端口。
- 打印每次请求的长度与消息类型，便于定位封包问题。

## 伪代码：先更新资源服务器，再获取服务器列表（不依赖版本回显）

> 目标：客户端启动后优先完成资源更新（通过目录服发现资源服），随后再拉取服务器列表进行业务连接。

```pseudo
function bootClient()
    // 1) 连接目录服务器
    dir = connectTcp(host: DIR_HOST, port: DIR_PORT)

    // 2) 查询资源服务器（策略优先低负载，数量限制 1）
    qRes = QueryServersRequest { type="resource", strategy="load", limit=1 }
    resList = send(dir, qRes) // returns QueryServersResponse
    if resList.servers.isEmpty() then
        fatal("没有可用的资源服务器")
    end
    resSrv = resList.servers[0]

    // 3) 连接资源服务器并查询版本
    res = connectTcp(host: resSrv.host, port: resSrv.port)
    qv = QueryVersionRequest { platform=PLATFORM }
    vr = send(res, qv) // returns QueryVersionResponse

    // 4) 按清单逐个资源包处理（忽略 update_available）
    for each bundle in vr.bundles
            // 优先使用返回的签名 URL（10 分钟有效期）
            if not empty(bundle.url) then
                data = httpGet(bundle.url)
            else
                // 后备方案：通过 GetBundleRequest 走TCP拿包体
                gb = GetBundleRequest { name=bundle.name, version=vr.latest_version }
                gr = send(res, gb) // returns GetBundleResponse
                assert(gr.success)
                data = gr.content
            end

            saveToDisk(pathFor(bundle.name), data)
            assert(sha256(data) == bundle.hash)
        end
    LOCAL_VERSION = vr.latest_version // 可选：本地维护版本号与资源清单
    close(res) // 资源服连接结束

    // 5) 资源更新完成后，再次向目录服查询业务服务器列表
    // 示例：选择登录服（策略优先低延迟，可按区域过滤，数量限制3）
    qLogin = QueryServersRequest { type="login", strategy="latency", region=REGION?, limit=3 }
    loginList = send(dir, qLogin)
    if loginList.servers.isEmpty() then
        fatal("没有可用的登录服务器")
    end
    // 选取第一项或根据自定义打分从列表中择优
    loginSrv = pickBest(loginList.servers)

    // 6) 连接登录服并获取令牌（如项目启用令牌制）
    lg = connectTcp(host: loginSrv.host, port: loginSrv.port)
    lr = send(lg, LoginRequest { account, password }) // returns LoginResponse
    token = lr.token // 后续访问其他服务时需携带
    close(lg)

    // 7) 访问其他服务（逻辑/战斗等），在包裹层携带令牌
    // 示例：连接逻辑服并查询签到状态
    qLogic = QueryServersRequest { type="logic", strategy="latency", limit=1 }
    logicSrv = send(dir, qLogic).servers[0]
    lgc = connectTcp(host: logicSrv.host, port: logicSrv.port)
    resp = sendWithEnvelope(lgc, QuerySignInStatusRequest { player_id }, token)
    close(lgc)

    // 结束：保留目录服连接或按需断开
    close(dir)
end

// 包裹层示例：将业务消息放入 Envelope 并附加令牌
function sendWithEnvelope(conn, payloadMessage, token)
    env = Envelope { type = payloadMessage.Descriptor.Name, payload = payloadMessage.ToByteString(), token = token }
    return send(conn, env)
end
```

要点说明：
- `QueryServersRequest` 支持 `strategy`（`load`/`latency`/默认心跳新鲜度）、`region`、`limit`，可用于过滤与排序。
- 资源服返回的 `bundles[].url` 可能包含签名参数（`token/sid/exp`），在有效期内直接按 HTTP 下载。
- 服务器不回显 `Envelope.version`；客户端可自行携带该字段，但应避免依赖其值做更新判断。
- 若项目启用令牌校验，访问逻辑/战斗等服务时需在 `Envelope.token` 携带登录服签发的令牌。
