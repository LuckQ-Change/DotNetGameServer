# 服务器部署文档

本文档介绍如何部署各服务（目录、登录、资源、逻辑、战斗）以及必要的配置项。支持本地开发与生产环境部署。

## 构建与产物
- 运行 `dotnet build` 或使用项目内打包脚本：
  - `pack.ps1` / `pack.bat` 生成 `dist/DotNetGameServer-Release-win-x64.zip`。
- 产物包含各服务 DLL 以及依赖库，可在 Windows 环境以 `dotnet` 或自带 EXE 启动（Window 程序为统一入口）。

## 配置文件
- 现在支持分层配置：`appsettings.json` + `appsettings.{ENV}.json` + 环境变量（通过 `ASPNETCORE_ENVIRONMENT` 指定环境）。
- `ServerHost` 会将 `appsettings` 中的配置映射到环境变量，兼容现有 `SimpleConfigLoader`（无需立刻重构业务代码）：
  - MySQL：`mysql.conn` 或分项 `mysql.{host,port,user,password,database}` → 环境变量 `MYSQL_*`。
  - 目录令牌密钥：`directory.tokenSecret` → 环境变量 `DIRECTORY_TOKEN_SECRET`。
  - 服务器运行参数：`server.{maxMessageSizeBytes,maxConcurrentConnections,receiveTimeoutMs,acceptBackoffMs}` → `SERVER_*` 环境变量。
  - 网络鲁棒性限速：`server.{maxBytesPerSecond,maxMessagesPerSecond,idleTimeoutMs}` → `SERVER_MAX_BPS/SERVER_MAX_MSGS/SERVER_IDLE_MS`。
  - 目录注册表（Redis/内存）：`directory.registry` 段用于选择注册表实现与连接方式。

示例 `appsettings.json`（开发默认使用内存，可切换为 Redis）：
```json
{
  "service": { "type": "directory", "port": 5500 },
  "mysql": { "host": "127.0.0.1", "port": 3306, "user": "root", "password": "password", "database": "game" },
  "heartbeat": { "region": "default", "capacity": 100, "intervalSeconds": 5, "host": "127.0.0.1" },
  "server": { "maxMessageSizeBytes": 1048576, "maxConcurrentConnections": 200, "receiveTimeoutMs": 10000, "acceptBackoffMs": 200 },
  "directory": {
    "tokenSecret": "changeme",
    "registry": {
      "mode": "memory",
      "redis": { "connectionString": "localhost:6379" }
    }
  }
}
```

示例 `appsettings.Production.json`（生产默认使用 Redis，连接串通过 Secret/环境变量注入）：
```json
{
  "service": { "type": "directory", "port": 5500 },
  "directory": {
    "tokenSecret": "__FROM_SECRET__",
    "registry": { "mode": "redis" }
  }
}
```

环境变量映射与优先级（DirectoryServer）：
- 优先读取 `appsettings` 键：`Directory:Registry:Mode`、`Directory:Registry:Redis:ConnectionString`。
- 未配置时回退到环境变量：`DIRECTORY_REGISTRY`、`REDIS_CONNECTION`。
- 最后回退到默认值：`mode=memory`、`connectionString=localhost:6379`。

参数化与运维调优（TTL 与清理周期）：
- 支持通过配置外部化以下参数（单位秒）：
  - `Directory:Registry:Redis:OfflineTtlSeconds`：目录在列表与查询中判定“离线”的心跳 TTL（默认 120）。
  - `Directory:Registry:Redis:RemoveTtlSeconds`：彻底移除过期服务器记录的 TTL（默认 600）。
  - `Directory:Registry:Redis:CleanupIntervalSeconds`：后台清理轮询间隔（默认 10）。
- 环境变量回退（若 appsettings 未配置）：
  - `DIRECTORY_REGISTRY_OFFLINE_TTL_SECONDS`、`DIRECTORY_REGISTRY_REMOVE_TTL_SECONDS`、`DIRECTORY_REGISTRY_CLEANUP_INTERVAL_SECONDS`。
- 调优建议：
  - 小容量/高波动环境可适当降低 `OfflineTtlSeconds`，以快速反映状态；高延迟跨区环境建议提高 TTL，避免短暂网络抖动导致误判离线。
  - `RemoveTtlSeconds` 不宜过短，确保运维有足够窗口观察离线状态；过长会增加残留键占用。
  - 清理间隔越短，Redis 负载越高；建议在 5-30 秒范围按负载调整。

生产部署建议：
- K8s 中将 `DIRECTORY_REGISTRY=redis` 放在 `ConfigMap`，将 `REDIS_CONNECTION`（含 `password=`）放在 `Secret`；我们已经在 `k8s/secret.yaml` 与 `k8s/deployment.yaml` 中完成示例。
- Docker Compose 使用 `${REDIS_PASSWORD}` 与 `REDIS_CONNECTION="redis:6379,password=${REDIS_PASSWORD}"` 的方式避免明文密码；参考 `docker-compose.yml`。

## 启动顺序
1. 目录服务器（`DirectoryServer.dll`）：提供服务发现与状态汇总。
2. 各业务服务器：资源、登录、逻辑、战斗；它们通过心跳上报到目录服务器。
3. 客户端通过目录获取入口后与目标服务进行交互。

## 运行方式
- 开发调试：使用 `Window.exe`（在 `dist/Window`）统一管理各服务启动与日志。
- 生产部署：使用统一启动器 `ServerHost.dll`，通过环境变量/参数指定服务类型与端口：
  - `ASPNETCORE_ENVIRONMENT=Production SERVICE=directory PORT=5500 dotnet src/ServerHost/bin/Release/net9.0/ServerHost.dll`
  - 或容器编排（见下文 Docker/K8s）。

## 端口与防火墙
- 目录服务器默认端口 `5500`。各业务服务器端口由启动时分配或配置决定。
- 开启相应端口的入站规则，并限制仅可信源访问（尤其生产环境）。

## 日志与监控
- 生产使用 `ServerHost` 的控制台日志，容器平台可聚合采集（Docker/K8s 标准输出）。
- `HeartbeatClientComponent` 定期向目录服务器上报状态（类型、端口、容量、在线状态）。

### 指标导出（Metrics）

- 模式选择：通过 `telemetry.metrics.mode` 配置导出模式，当前默认启用 OTLP。
  - `otlp`：通过 OTLP/HTTP 将指标推送至 OpenTelemetry Collector（已实现）。
  - `prometheus`（计划）：暴露 `/metrics` 端点供 Prometheus 抓取（将在后续版本通过 ASP.NET Core 管道集成）。
- 配置示例（`src/ServerHost/appsettings.json`）：
  ```json
  "telemetry": {
    "metrics": {
      "enabled": true,
      "mode": "otlp",
      "otlp": { "endpoint": "http://otel-collector:4318" }
    }
  }
  ```
- 环境变量映射：
  - `TELEMETRY_METRICS_ENABLED=true`
  - `TELEMETRY_METRICS_MODE=otlp`
  - `OTLP_ENDPOINT=http://otel-collector:4318`
- Prometheus Operator 示例：
  - Service 与 ServiceMonitor（用于将来 `/metrics` 暴露时启用）：见 `k8s/serverhost-metrics-service.yaml` 与 `k8s/serverhost-servicemonitor.yaml`。
  - 当前 OTLP 模式下，请在 Collector 中启用 `otlp` receiver 与相应 exporter（如 `prometheusremotewrite`）。

## 容器化与编排
- Docker：根目录 `Dockerfile` 提供多阶段构建；`docker-compose.yml` 定义各服务容器、端口映射与环境变量；日志采集依赖容器运行时收集标准输出。
  - 示例：`docker compose up -d directory login logic battle resource`
- Kubernetes：`k8s/` 目录包含 `deployment.yaml`、`service.yaml`、`configmap.yaml`、`secret.yaml`。
  - 就绪/存活探针采用 `tcpSocket` 指向服务监听端口，无需 HTTP 健康端点。
  - 敏感参数（如 `DIRECTORY_TOKEN_SECRET`）存放在 `Secret`，非敏感运行参数放在 `ConfigMap`。

## 安全与密钥
- 生产环境禁用默认密钥：`dev-secret`/`changeme`/`changeme-dev` 等默认值将导致进程在启动时失败（fail fast）。
- Redis 连接串必填：当 `Directory.Registry=redis` 时，`REDIS_CONNECTION` 必须通过 Secret 注入，且不得为 `localhost` 或包含默认口令（如 `changeme`）。

## 启动器分离
- Window.exe 保留开发调试用途；生产统一由容器编排或服务管理器启动 `ServerHost`。

## 数据库
- 如果登录或逻辑依赖数据库，请确保配置了正确的 MySQL 连接串并初始化表结构。

## 常见问题
- 服务未在目录显示：检查心跳配置与目录地址端口；确认服务已监听端口且 `ListeningPort` 可用。
- 客户端无法连接：检查防火墙与端口占用；确认服务进程状态与日志。
- 包过大被拒绝：调整 `server.maxMessageSizeBytes` 并重启服务。
