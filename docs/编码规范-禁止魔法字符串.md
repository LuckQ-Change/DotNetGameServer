# 编码规范：禁止魔法字符串（硬编码明显字符）

为提升可维护性与可测试性，项目禁止在代码中直接使用具有业务含义的字符串字面量（俗称“魔法字符串”）。

## 规则

- 不允许在 C# 代码中直接出现业务含义明显的字符串字面量（例如配置键、环境变量名、状态名、事件名、路由、队列/Topic 名称、错误码字符串、鉴权角色等）。
- 如确需使用，请遵循以下方式之一：
  - 抽取为常量（static readonly / const），集中管理；
  - 抽取为枚举（enum）；
  - 抽取为资源文件（.resx），用于 UI 文本与多语言；
  - 抽取到配置（appsettings/环境变量/Secret），通过配置读取。

## 强制执行

- 已启用 SonarAnalyzer.CSharp 并将规则 S1192（重复字符串字面量）设为 error：当同一字符串在多个位置重复出现时，编译会失败，提示“请抽取为常量或资源”。
- 后续可以结合 Code Review 与静态扫描，针对单次出现但具有明显业务含义的字符串进行人工判定与整改。

## 例外情况

以下情形可以使用字符串字面量：

- 日志中格式化占位符（例如 "Processed {Count} items"），但建议将固定消息文本统一到资源或常量中；
- 单元测试中 Given/When/Then 的临时字符串，或仅在测试上下文中使用的样例值；
- 一次性、短生命周期、对业务无命名约束的临时字符串（例如 string.Empty、"ok" 等微不足道的值）。

不允许的情形示例：

- 配置键：config["directory:registry:mode"] 应改为使用常量 ConfigKeys.Directory.Registry.Mode；
- 环境变量名：Environment.GetEnvironmentVariable("DIRECTORY_TOKEN_SECRET") 应改为使用常量 EnvVars.DirectoryTokenSecret；
- 角色/权限名："admin"、"operator" 等应统一常量或枚举定义。

## 推荐做法

1. 在 src/Shared/Constants 下集中维护常量/枚举：
   - 配置键常量（ConfigKeys.cs）
   - 环境变量名常量（EnvVars.cs）
   - 领域枚举（如 ServiceType、RegistryMode 等）
2. UI 文本统一进入 Resources（.resx），通过本地化加载；
3. 新增字符串时，先判断其业务含义与复用概率，若可能复用或影响兼容性，必须抽取。

## 迁移建议

- 将在代码中重复出现的字符串批量提取到常量；
- 对于仅出现一次但显著影响行为或协议的字符串（如路由、事件名、键名），也应提取；
- 配置与密钥相关字符串从代码移至 appsettings/环境变量/Secret，并在代码中通过常量化的键名读取。

## 关联配置

- .editorconfig 已设置：
  - dotnet_diagnostic.S1192.severity = error
- Directory.Build.props 已引入：
  - SonarAnalyzer.CSharp，启用 .NET 分析器
