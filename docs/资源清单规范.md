# 资源清单规范（Resource Manifest）

本规范说明资源服务器返回的版本与资源包信息结构，客户端据此完成热更新与资源下载。

## 总览
- 查询接口：`QueryVersionRequest/Response`
- 资源条目：`ResourceBundleInfo`
- 获取单包接口：`GetBundleRequest/Response`（示例用，生产可用 HTTP/CDN）

## QueryVersionResponse
- `update_available`：`bool`，是否存在可更新内容。
- `latest_version`：`string`，当前最新资源版本（语义/构建号）。
- `bundles`：`ResourceBundleInfo[]`，需要更新的 AB 列表。

返回示例（伪代码）：
```
QueryVersionResponse {
  update_available: true,
  latest_version: "1.2.3",
  bundles: [
    { name: "characters", hash: "ab12...", size: 1048576, url: "https://cdn.example.com/res/characters.ab?sid=...&exp=..." },
    { name: "ui",         hash: "cd34...", size: 524288,  url: "https://cdn.example.com/res/ui.ab?sid=...&exp=..." }
  ]
}
```

## ResourceBundleInfo
- `name`：`string`，AB 包名称。
- `hash`：`string`，文件哈希（建议 `SHA256` 或 Unity Hash）。
- `size`：`int`，字节大小（用于进度与校验）。
- `url`：`string`，下载地址；可带鉴权签名参数（如 `token/sid/exp`）。

下载与校验流程建议：
- 使用 `url` 直接发起 HTTP 下载（优先 CDN）。
- 完成后校验文件哈希与大小，与 `hash/size` 对比一致再入库。
- 失败重试策略：指数退避，最多 3 次；失败上报日志与指标。

## GetBundleRequest/Response（示例）
- `GetBundleRequest.name`：AB 名称。
- `GetBundleRequest.version`：目标版本号（兼容历史版本）。
- `GetBundleResponse.success`：是否成功。
- `GetBundleResponse.message`：提示消息。
- `GetBundleResponse.content`：文件内容（二进制，示例用途）。
- `GetBundleResponse.hash/size`：哈希与大小（用于校验）。

生产建议：
- 使用 CDN/对象存储（S3、OSS、COS）托管资源；`url` 指向 CDN 域名。
- 开启签名与有效期控制（`sid/exp`），避免盗链与过期访问。
- 设置 `Cache-Control` 与版本化路径（如 `/{version}/...`）便于回滚与灰度。

## 客户端约定
- 资源下载优先使用 `ResourceBundleInfo.url`，避免走游戏服务通道。
- 校验 `hash/size` 与重试；失败时记录本地日志与上报。
- 服务不回显 `Envelope.version`；客户端可携带该字段但不要依赖其值做更新判断。

## 指标与监控（可选）
- 记录下载成功/失败次数、平均耗时、重试次数。
- 记录校验失败次数，按包名与版本聚合以定位问题。

## 安全与合规
- 资源 `url` 建议签名且设置最短必要有效期。
- 从日志中剔除敏感签名参数，避免泄露。
