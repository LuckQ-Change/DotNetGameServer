# 项目说明文档

本项目为一个基于 .NET 的多服务游戏服务器示例，采用强类型消息（Protobuf）与组件化架构，包含目录、资源、登录、逻辑、战斗等模块。

## 架构概览
- 核心库 `Core`：
  - 基类：`BaseGameServer`（连接管理、消息派发、组件生命周期）。
  - 消息接口：`IStrongMessageHandler<TReq,TResp>` 与 `StrongHandlerInvoker<TReq,TResp>`。
  - 组件接口：`IServerComponent`、`IServerContext`。
  - 组件访问扩展：`ServerContextExtensions.GetRequiredComponent<T>()`、`TryGetComponent<T>(out T?)`。
  - 心跳组件：`Core.Components.HeartbeatClientComponent`（向目录上报状态）。
  - 配置：`Core.Config.SimpleConfigLoader`（读取 `appsettings.json` 与环境变量）。
- 目录服务器 `DirectoryServer`：服务发现与状态汇总（`QueryServersRequest/Response`）。
- 资源服务器 `ResourceServer`：版本与资源包（`QueryVersion`/`GetBundle`）。
- 登录服务器 `LoginServer`：登录鉴权（示例，按实际 Handler 扩展）。
- 逻辑服务器 `LogicServer`：业务逻辑（示例为七日签到）。
- 战斗服务器 `BattleServer`：战斗相关逻辑与简易 GC 系统。
- 服务宿主 `ServerHost`：统一启动与托管各个游戏服务器。

## 消息与路由
- 所有服务器在构造函数中通过 `RegisterStrongMessageHandler<TReq,TResp>(handler)` 注册强类型处理器；系统已移除旧的字符串路由与字节处理接口。
- Protobuf 类型命名空间统一为 `DotNetGameServer`（由生成器产生）。

## 关键流程与约定
- 服务心跳：各服务器使用 `HeartbeatClientComponent` 将 `type`、`port`、`status`、`capacity` 上报到目录。
- 目录发现：客户端使用 `QueryServersRequest` 获取目标服务地址，避免硬编码端口。
- ECS 支持：示例中 `BattleServer` 使用 `EcsWorldComponent` 并注册 `BattleGcSystem`（TTL 30 分钟）。

### 协议版本字段
- `Envelope.version` 为可选字段；服务器不根据该字段进行兼容性检查，并且响应中不再回写该值。
- 客户端应避免依赖服务端的版本回显，将版本判定逻辑完全交由资源清单（`QueryVersion` 返回的 `latest_version` 与 `bundles`）。

### 目录密钥与心跳认证
- 目录密钥读取：`Core.Config.SimpleConfigLoader.LoadDirectoryTokenSecret(AppContext.BaseDirectory)` 从配置读取目录签名密钥（找不到时使用开发默认 `dev-secret`）。
- 心跳认证：业务服上报心跳时，客户端需在包裹层 `Envelope.token` 携带签名令牌；目录服在 `HeartbeatMessageHandler` 中使用 `TokenSigner.TryVerifyHeartbeat(token, req.Id, secret, ...)` 校验令牌是否与服务器ID绑定且未过期。
- 失败处理：校验失败返回 `HeartbeatResponse { Accepted = false }`，并在日志打印 `[目录] 心跳被拒绝：签名无效或缺失`。
 - 指标上报：
   - 目录服心跳相关（DirectoryMetricsComponent）：
     - `directory_heartbeat_accept_total`：心跳认证通过次数（Counter）
     - `directory_heartbeat_rejected_total`：心跳认证被拒绝次数（Counter）
     - `directory_heartbeat_error_total`：心跳处理异常次数（Counter）
   - 目录服对 Redis 的操作（RedisServerRegistryComponent，经 CoreTelemetry.Meter 暴露）：
     - `directory_redis_connect_total`：Redis 连接成功次数（Counter）
     - `directory_redis_connect_fail_total`：Redis 连接失败次数（Counter，标签：exception）
     - `directory_redis_op_latency_seconds`：Redis 操作耗时（Histogram，标签：op）
     - `directory_redis_errors_total`：Redis 操作异常次数（Counter，标签：op、exception）
   - 采集对接：可使用 OpenTelemetry SDK 或 Prometheus.net 读取上述 `System.Diagnostics.Metrics` 指标，按需导出到 OTEL/Prometheus。

## 构建与打包
- `dotnet build` 进行编译；`pack.ps1` 生成 `dist` 包。
- `src/Shared/Protos` 目录下的 `.proto` 文件定义了服务间的通信协议。执行 `tools/gen-proto/gen-proto.bat` 或 `gen-proto.ps1` 脚本可以自动生成C#代码。

## 目录结构简述
- `src/Core`：核心库、组件、配置、消息支持。
- `src/DirectoryServer`：目录服务与其消息处理。
- `src/ResourceServer`：资源服务与其消息处理。
- `src/LoginServer`：登录服务与其消息处理。
- `src/LogicGameServer`：逻辑服务与签到示例。
- `src/BattleServer`：战斗服务与 ECS 示例。
- `src/Shared`：公共 Proto 定义与共享工具（如令牌签名）。
- `src/Window`：桌面管理端。
- `tools`：Proto 生成脚本。
 - `tools/gen-proto`：Proto 生成脚本与批处理封装（`gen-proto.ps1`、`gen-proto.bat`）。

## 后续扩展建议
- 在目录服务器内支持按负载或延迟的智能挑选策略。
- 引入统一鉴权与令牌校验中间件到各业务服务。
- 为资源下载引入 CDN/鉴权签名。
- 扩展监控（Prometheus/OTEL）与结构化日志。
- 告警建议（示例阈值，需按实际负载与SLO调整）：
   - Redis 可用性：`directory_redis_connect_fail_total` 在 5 分钟窗口内突增（>3 次）或持续失败；或外部 `redis_up==0`（需部署 redis_exporter）。
   - 操作延迟：`directory_redis_op_latency_seconds{op}` 99% 分位 > 100ms 持续 5 分钟。
   - 错误率：`sum(rate(directory_redis_errors_total[5m])) / sum(rate(请求总数[5m])) > 1%`。
   - 容量与资源（通过 redis_exporter 或 Redis 自身指标）：内存使用 > 80%、拒绝连接数、主从复制延迟异常等。

### Redis 接入配置（appsettings 与环境变量）
- 目录服务支持通过 `appsettings` 或环境变量配置注册表存储：
  - `Directory:Registry:Mode`：`memory` 或 `redis`。
  - `Directory:Registry:Redis:ConnectionString`：例如 `host:port,password=***`，支持 `ssl=True`。
  - 环境变量回退：`DIRECTORY_REGISTRY`、`REDIS_CONNECTION`。
- 生产环境建议：
  - 将 `DIRECTORY_REGISTRY=redis` 置于 ConfigMap；将含密码的 `REDIS_CONNECTION` 置于 Secret。
  - K8s 示例已在 `k8s/configmap.yaml`、`k8s/secret.yaml`、`k8s/deployment.yaml` 提供；Docker Compose 示例见根目录 `docker-compose.yml`。

### Redis TLS/证书（可选增强）
- 密码鉴权已支持，若需 TLS：
  - 基础 TLS（单向）：在连接串中加入 `ssl=True`（StackExchange.Redis 支持），并在 Redis 端开启 TLS（Redis 6+）。
  - 双向证书（客户端证书）：需要使用 `StackExchange.Redis` 的 `ConfigurationOptions` 方式在代码中指定证书选择与验证委托；当前代码使用连接串，不支持客户端证书，若有需求我们可以新增配置段并改造 `RedisServerRegistryComponent`：
    - `Directory:Registry:Redis:Ssl`: `true/false`
    - `Directory:Registry:Redis:SslHost`: 服务器证书主机匹配名
    - `Directory:Registry:Redis:ClientCertificate:Path/Password`: PFX 路径与密码
    - 并改为 `ConnectionMultiplexer.ConnectAsync(ConfigurationOptions)` 加载证书。
- 证书与密钥同样应存放在 Secret 中，通过挂载或环境变量传递路径与口令。

### 数据库迁移与现代化

为了统一技术栈并利用现代化的 ORM 框架，项目已从 `MySqlConnector` 完全迁移到使用 **PostgreSQL** 和 **Entity Framework Core**。

#### 1. GameDbContext

`src/Core/Db/GameDbContext.cs` 是数据库交互的核心。它继承自 `DbContext` 并定义了所有需要持久化的数据模型（`DbSet`）。

```csharp
// src/Core/Db/GameDbContext.cs
using Microsoft.EntityFrameworkCore;

namespace Core.Db;

public class GameDbContext : DbContext
{
    public GameDbContext(DbContextOptions<GameDbContext> options) : base(options)
    {
    }

    // 在这里定义您的数据模型
    // public DbSet<Player> Players { get; set; }
    // public DbSet<Item> Items { get; set; }
}
```

#### 2. 依赖注入

`GameDbContext` 已在 `ServerHost` 中配置了依赖注入。这意味着您可以在任何游戏服务器（如 `LoginGameServer`, `BattleGameServer` 等）的构造函数中直接注入 `GameDbContext` 来访问数据库。

```csharp
// src/ServerHost/Program.cs
builder.Services.AddDbContext<GameDbContext>(options =>
    options.UseNpgsql(builder.Configuration.GetConnectionString("DefaultConnection")));
```

#### 3. 连接字符串

数据库连接字符串在 `appsettings.json` 文件中配置。请根据您的本地 PostgreSQL 环境修改它。

```json
// src/ServerHost/appsettings.json
{
  "ConnectionStrings": {
    "DefaultConnection": "Host=localhost;Port=5432;Database=game;Username=postgres;Password=password"
  }
}
```

## Rider 开发环境配置

在 JetBrains Rider 中开发此项目非常高效。请遵循以下步骤进行配置：

### 1. 打开项目

直接使用 Rider 打开解决方案文件 `DotNetGameServer.sln`。Rider 会自动加载所有项目及其依赖项。

### 2. .NET SDK

请确保您已安装 **.NET 8 SDK**。Rider 通常会自动检测已安装的 SDK。您可以在 `File | Settings | Build, Execution, Deployment | Toolset and Build` 中检查和配置 .NET CLI 的路径。

### 3. 数据库配置

项目使用 PostgreSQL 数据库。

- **安装 PostgreSQL**：如果您本地没有安装，请先安装并运行一个 PostgreSQL 实例。
- **配置连接字符串**：打开 `src/ServerHost/appsettings.json` 文件，修改 `DefaultConnection` 连接字符串以匹配您的数据库设置（主机、端口、用户名、密码）。
- **Rider 数据库工具**：强烈建议使用 Rider 内置的数据库工具。
    1.  打开 `View | Tool Windows | Database` 视图。
    2.  点击 `+` -> `Data Source` -> `PostgreSQL`。
    3.  填入您的数据库连接信息，即可在 IDE 中方便地浏览数据表、执行 SQL 查询和管理数据库。

### 4. Protobuf / gRPC

项目中的 `.proto` 文件会自动进行代码生成，无需手动运行脚本。当您构建解决方案时 (`Build | Build Solution`)，`Grpc.Tools` 包会自动将 `.proto` 文件编译成 C# 代码。Rider 对 `.proto` 文件提供语法高亮和智能提示支持。

### 5. 运行与调试

您需要为不同的服务创建运行/调试配置。

#### a. 运行游戏服务器 (`ServerHost`)

1.  在右上角的配置下拉菜单中，点击 `Edit Configurations...`。
2.  点击 `+` -> `.NET Project`。
3.  **Name**: `ServerHost`
4.  **Project**: 选择 `ServerHost` 项目。
5.  **Program arguments**: 您可以在此指定要启动的服务器类型，例如 `Login` 或 `Battle`。请查阅 `ServerHost/Program.cs` 以了解启动参数的实现细节。
6.  点击 `OK` 保存。现在您可以选择 `ServerHost` 配置并点击“运行”或“调试”按钮。

#### b. 运行管理后台 (`AdminPanel`)

1.  同样地，创建一个新的 `.NET Project` 配置。
2.  **Name**: `AdminPanel`
3.  **Project**: 选择 `AdminPanel` 项目。
4.  Rider 会自动识别这是一个 ASP.NET Core 项目，并为您配置好浏览器启动等设置。
5.  点击 `OK` 保存。选择 `AdminPanel` 配置并运行，即可启动 Web 管理后台。

通过以上配置，您就可以在 Rider 中顺利地进行开发和调试了。
